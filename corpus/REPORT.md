# Corpus report — how far is the native SHAVE toolchain from *arbitrary C*?

Measurement task; read-only on every foreign tree. Everything below is generated by
`corpus/run_corpus.sh` (compile -> assemble -> link -> structural validation) plus
`corpus/tools/`; raw per-kernel logs live in `corpus/logs/` and verbatim diagnostics
in `corpus/DIAGNOSTICS.md`. `corpus/DEFECTS.md` holds the curated ranked defect list
that is appended verbatim at the end.

## Method

Pipeline = the exact npunlock contract, driven through a toolchain root:

```
compile:  $TC/bin/moviCompile -cc1 -triple shave -target-cpu 3720xx -S -O2 -x c entry.c \
              -ffunction-sections -fdata-sections -Icorpus/include [-D…] -o -   < kernel.c
assemble: $TC/bin/moviAsm --cv 3720xx --noSPrefixing                              < kernel.s
link:     $TC/bin/moviLLD -flavor gnu -EL -e controlled_act -z max-page-size=0x10 \
              --gc-sections [lib/mlibm.a] -T npunlock/src/shavecc/shave_kernel.ld kernel.o -o -
validate: python3 corpus/tools/validate_elf.py kernel.elf
```

`validate_elf.py` re-implements `npunlock_parse_shave_elf` (`src/common/elf32.c`)
check for check: ELF32 LE ET_EXEC EM_SPARC, `.text` PROGBITS at `0x1d000000` equal to
`e_entry`, `.arg.data` empty at `0x1e000000`, no non-empty `REL`/`RELA` sections, no
undefined symbols, `.text` covered by a `PT_LOAD` with `R+X`. It returns OK on the
gold `add1-fp16.elf` and on our own output, so the validator is anchored.

Every stage runs under `timeout 25`; timeouts would be recorded as `HANG` (**none
observed** — no compile in the corpus hung).

**Caveat for the word "pass":** pass means *the linked ELF has the structure npunlock
expects*, not that the code executes correctly. FINDINGS.md R2-R5 document

conflicts) that structural validation cannot see.

## Headline (revision A)

* **13/33 corpus kernels** and **15/62 minimal repros** complete the whole
  compile+assemble+link+validate path.
* **Every failure is a compile-stage failure.** No assembler rejection, no linker
  rejection (except the two probes that deliberately omit the entry symbol), and no
  structural-validation failure on any produced ELF.
* Failure taxonomy over both corpora (95 units):
  * `ISel: Cannot select`: 30
  * `pass`: 28
  * `backend fatal (report_fatal_error)`: 17
  * `calls unsupported`: 16
  * `linker message bug`: 2
  * `crash (SIGABRT)`: 2
* No hangs; the only process-level crash is the register-spill abort (`r60`, `r61`).
* The repository's own shipped example kernels (`examples/example_gelu*.py`) and the
  `npu3720_kernel.h` link-compat path (`a02`) **do not compile**, so the gap is not
  academic — the documented user surface is already outside what the toolchain builds.

### Notes for "arbitrary user C"

* The most damaging pattern is that failures are *hard stops at `-O2`*: the compiled
  surface is not "arbitrary C minus a few APIs", it is "C that happens to avoid
  calls, signed `<`, int↔float casts, `/`/`%` by constants, globals, locals with
  runtime indices, fp compares, and >34 live values". Ordinary kernels (gelu,
  softmax, conv, layernorm) hit at least 3–4 of these in the first screen of code.
* Zero assembler/linker/structural failures means the remaining work is *frontend of
  the backend* (ISel patterns + call lowering + frame/global addressing), not the
  encoding work that the ISA stream owns.
* Structural pass ≠ correct execution: FINDINGS.md R2–R5 (load latency 6, branch
  delay 6, `CMU` flag semantics, LSU0/LSU1 conflict) mean a structurally valid ELF
  can still write nothing to the output window. This corpus measures *buildability*;
  the two axes must both be green before "arbitrary C" is real.
* The gated acceptance fixture `a01` still builds (384 B `.text` on revision A,
  432 B on revision C) — the corpus does not regress the gate, it quantifies the
  distance beyond it.

### The three highest-impact fixes

1. **Implement `LowerCall` (and the callee-save/return-address convention).** One
   function unblocks the largest single group: internal helpers, all of `mlibm.a`,
   varargs, recursion, indirect calls, and every i64/double libcall. Without it the
   repo's own `examples/*.py` cannot work at all.
2. **Fill the arithmetic/compare ISel surface: int↔float conversions, signed
   relational compares, `mulhu`/`sdivrem`, `fcmp` + FP value-selects.** This is the
   set that ordinary C reaches within its first few lines, and it is cheap
   relative to #1 (single DAG patterns/legalizations, no ABI design). Class 2 is
   additionally a *regression* relative to the 12:53 build.
3. **Give the target a memory model: global/data address materialization (also fixes
   jump tables) and stack frames (spill slots) — and make the no-spill case
   impossible to reach.** Fixing only the graceful-abort path stops the compiler
   from core-dumping (class 7), but local arrays/globals/switches (classes 5, 6) need
   real addressing; a jump-table `br_jt` also needs a PC-relative or absolute data
   base that the vendor emitting stream actually supports.
